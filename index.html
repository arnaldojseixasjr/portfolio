// 02 — sintese_teorica

Os 3 Pilares do Dev Visível

Toda a engenharia de uma marca técnica se sustenta em três colunas que se reforçam mutuamente: o GitHub como vitrine, a organização dos repositórios e o LinkedIn como amplificador. Use as abas abaixo para alternar entre eles.

Identidade & Perfil Otimizado

A primeira coisa que um recrutador vê não é seu código — é a sua identidade. Em 10 segundos, a foto, o nome e a bio já formaram a primeira impressão. Se esse trio está mal resolvido, nada mais do perfil será avaliado.

  • Foto profissional e nítida

    Rosto visível, fundo neutro, boa iluminação. Nada de avatar de anime, foto de praia ou logo de time.

  • Nome completo real

    "Arnaldo Seixas" abre portas; "dev_ninjaxX123" fecha. Seu nome é pesquisável no LinkedIn e em referências.

  • Username amigável e estável

    Curto, sem números aleatórios. Ex.: @arnaldo-seixas. Não mude depois que começar a ser referenciado.

  • Bio objetiva com contatos

    Stack + foco + e-mail + portfólio em 2 linhas. É o seu "elevator pitch" permanente.

O README Especial do Perfil

O GitHub tem um truque pouco conhecido: se você criar um repositório com o mesmo nome do seu username, ele vira automaticamente o "Profile README" — uma página de apresentação em Markdown que aparece no topo do seu perfil.

  1. 1

    Crie um repositório chamado exatamente arnaldo-seixas/arnaldo-seixas

  2. 2

    Adicione um arquivo README.md na raiz

  3. 3

    Marque a caixa "Public" e inicialize com README

  4. 4

    Edite o README contando quem você é, o que domina e onde te achar

O GitHub avisa no próprio repositório:

"arnaldo-seixas/arnaldo-seixas is a ✨special ✨ repository: its README.md will appear on your profile!"

Elementos Visuais

Badges do Shields.io e emojis do GetEmoji transformam um README monótono em um painel de "dashboard" legível a 3 metros de distância. Eles não são enfeite — são sinais rápidos de autoridade técnica.

A Regra dos 6 Fixados

Recrutadores não têm tempo de escavar 47 repositórios. Eles olham os 6 pinned — o "showcase" que você curador. Esses 6 devem contar uma história coesa, não um cemitério de "exercício-aula-3".

Erro comum

Fixar 6 "hello-worlds" achando que quantidade impressiona. Não impressiona — sinaliza imaturidade.

Postura certa

6 projetos completos, deployados e documentados — cada um representando uma stack ou domínio diferente.

Projetos Simples Que Impressionam

Você não precisa de um "Instagram clone". Precisa de projetos pequenos, mas irrepreensíveis: que resolvem um problema real e mostram atenção aos detalhes — coisa que 95% dos iniciantes ignoram.

Jogo da Memória

Acessibilidade (teclado + ARIA), placar, tema dark/light. Mostra a11y + state.

Consumo de API (CEP/CEP-lookup)

Skeleton loading, cache local, tratamento de erros. Mostra UX + robustez.

Lista de Tarefas com Persistência

IndexedDB / localStorage, PWA instalável. Mostra offline-first.

Os 4 detalhes que diferenciam: código limpo, tratamento de erros, atenção a UI/UX e resolver problemas reais.

README do Projeto

O README é o vendedor silencioso do seu repositório. Ele responde a 4 perguntas que um recrutador faz em 30 segundos: o que é, com o que foi feito, como rodo e onde posso ver funcionando.

Headline Estratégico & "Sobre"

A headline do LinkedIn é o SEO do seu perfil: ela aparece em toda busca e em todo comentário que você faz. Não escreva "Desenvolvedor" — escreva a solução que você entrega.

Headline fraca

"Desenvolvedor | Buscando recolocação"

Headline estratégica

"Desenvolvedora Front-end React | Construo interfaces acessíveis que convertem visitantes em usuários"

Narrativa do "Sobre"

Conte a história de forma humana e engajadora: por que você entrou na tecnologia, que problema você se empolga em resolver, o que já construiu e para onde quer ir. Evite jargão — fale como se explicasse para um colega de turma.

Engenharia de Conteúdo — 1 Projeto = 5 Posts

O erro mais comum: postar uma vez quando termina um projeto e nunca mais tocar no assunto. O acerto: decompor um único projeto em 5 ângulos diferentes, gerando uma linha editorial de semanas. Cada post educa, atrai e direciona para o seu GitHub.

1

O Anúncio

O problema e a solução. "Construí um app que resolve X porque Y."

2

O Desafio Técnico

O bug ou dificuldade superada. Mostra o pensamento, não só o resultado.

3

O Aprendizado

A nova ferramenta/conceito que dominou. Conteúdo educativo = autoridade.

4

A Demonstração

Vídeo/GIF do projeto rodando. Proof > talk. Narração opcional via áudio.

5

O Pedido de Feedback

Compartilha o link do GitHub na comunidade. Abre conversa genuína.

Ciclo virtuoso: 5 posts → 5 chances de ser visto → 5 convites para conversa → 1 projeto vira 5 oportunidades de networking real. Repita com cada projeto novo.

Networking Estratégico — Construção de Relacionamentos Genuínos

Networking não é coletar conexões — é cultivar relacionamentos com sentido. A meta não é ter 2.000 contatos, mas ter 50 pessoas que te conhecem pelo que você entrega. As 4 práticas abaixo formam um sistema replicável.

Ajudar

Responder dúvida em fórum/Discord sem esperar nada em troca. Ajudar é o atalho mais rápido para ser lembrado.

Pedir ajuda

Pergunta bem feita = demonstra estudo e abre conversa. Sêniores adoram ajudar quem mostra que tentou.

Participar de eventos

Meetups, hackathons, lives. Compareça, anote 3 nomes, mande mensagem depois. O "depois" é o que vira relação.

Interagir com autoridade

Comente posts de referências da área com insight próprio, não só "🔥 show!". Comentários com substância são mini-palestras.
